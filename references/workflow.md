# EPUB 翻译工作流

## 1. 定义本次交付

从用户要求确定源书、目标语言/地区、试译或全书范围、电脑版/手机版及格式偏好。默认保持原作表达和段落，译文单语呈现；用户要求双语或改写时记录例外。先查看既有项目再创建文件，不因缺少可选偏好阻塞已经明确的任务。

## 2. 建立可核验原文

按 [提取参考](extraction.md) 清点 EPUB，确认阅读顺序、导航、图片、注释和复杂内容，保留原始文件哈希。生成有来源映射的 Markdown 章节。原文提取本身也要抽样对照阅读器，尤其是表格、公式和脚注。提取缺失时先修复，不能把残缺 Markdown 当完整原文翻译。

## 3. 翻译与校对

按 [翻译参考](translation.md) 创建术语表，完成第一遍；再逐段进行第二遍。大书按章或稳定段落范围推进，每个范围完成后立即保存。按 [状态参考](project-state.md) 记录源文和译文版本、覆盖范围以及待处理项，便于跨会话续译。

## 4. 构建可阅读版本

按 [构建参考](build.md) 核对正文白名单，合并清洁稿、修复跨章锚点和资源路径，生成标准版和独立手机版。只重建受影响的构建产物，正式译稿保留人工作业痕迹和追溯信息。

## 5. 验收与交付

按 [检查参考](validation.md) 运行脚本、EPUBCheck和实际阅读器检查；回查章节映射、译名表和校对覆盖。检查失败要有明确处理结果。用户要预览可先交付标明范围的预览版，不能把部分完成写成全书完成。

最后报告：处理的原书版本与范围、两遍进度、成品位置、检查结果、仍有的具体限制。不要仅报“文件已生成”。
