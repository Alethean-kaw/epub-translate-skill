# EPUB 提取、顺序与资源

## 清点和适用性

先用 `inspect` 获取原书 SHA-256、OPF 路径、manifest/spine 和 `linear` 属性。脚本仅输出清单，不自动解包或转 Markdown。包内文档按 `container.xml` 找到 OPF；不要寻找固定名或按 ZIP/文件名字母排序。

- 多 rendition：脚本 inspect/QC 只检查第一个，compare 拒绝直接比较。人工选定版本后再建立项目。
- `META-INF/encryption.xml` 不一定是 DRM，也可能是字体混淆。检查算法与资源；不要仅见此文件就宣称无法处理。
- 实际加密且无法读取的正文：记录阻塞，使用用户合法提供的可读版本，不假装成功提取。
- 固定版式、扫描页、漫画、SVG 正文、音视频/媒体叠加、复杂 MathML：单列处理范围。必要时 OCR 并逐页核对；此技能脚本不提供 OCR，也不能保证重排版复现。
- 脚本拒绝超限 ZIP、危险路径、重复条目、符号链接、加密 ZIP 条目、XML 实体声明和含 NUL 的 XML（包括 UTF-16）。保留源文件，诊断后用适用工具处理，不直接关闭限制。

## 按 spine 建立章节映射

逐项记录 `spine_index → manifest id → package-relative href → source chapter → translated chapter`，保留原始标题和 `linear=no` 信息。后者是辅助阅读属性，不表示内容可删除。

用 EPUB3 nav 或 EPUB2 NCX核对标题、层级和正文锚点。一个 spine 文件可以包含多个逻辑章，一章也可能横跨多个文件：保持来源映射，不把文件数误报为章数。重复目录、纯装饰页可经内容核对后排除；版权页、献词、前言、索引、书目、附录和注释默认保留。

## 安全读取与转换

按需读取 ZIP 成员。若另写解包程序，先检查解码/规范化后的路径位于目的目录内，拒绝绝对路径、`..` 越界、符号链接和资源超限；不可直接对任意输入调用无检查的 `extractall`。不要获取书籍中的远程 URL。

可用 Pandoc 或 XHTML 解析器逐项转换，随后对照原始 XHTML/阅读器；不能假定任意 HTML→Markdown 转换无损。保留标题层级、段落次序、列表、引用、强调、代码、表格、ruby、上下标和语言/方向属性。Markdown 无法表达的结构可使用经过检查的 XHTML 或单独资产，记录处理理由。

每章建议用唯一的显式 ASCII 锚点，例如 `{#ch-001}`，避免译名变更导致跨章链接失效。将原 XHTML 的文件/片段引用映射为稳定锚点；别只改可见链接文字。若正文引用页码，区分原版页码与新 EPUB 位置，不凭空换算。

## 图片、注释与数学内容

- 复制本地图片并建立原路径→新路径映射；不同目录同名图片不能互相覆盖。
- 保留图序、图注、alt、宽高意图和引用位置。SVG 等资源需额外验证内部依赖，脚本不会完整解析 CSS、字体或所有媒体关系。
- 脚注/尾注保留标记、正文、目标和返回链接。合并章节时将局部重复注释 ID 改为全书唯一 ID，并同步所有引用。
- 公式保留源码/MathML/图片及编号；逐一核对上下标、希腊字母、单位和正负号。表格保留行列、合并单元格、表头和说明，不能擅自转成丢失关系的段落。
- 排版换行可规范化；断词连字符、诗歌换行、代码缩进和段落边界需要依据原文判断，不做全书盲目替换。

提取完成后核对 spine 覆盖、首尾文本、注释/图片数量及至少每种复杂结构的实例。对遗漏记录明确文件/锚点/段落，不用“可能有格式问题”代替可定位问题。
